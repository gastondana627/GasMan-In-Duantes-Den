# GasMan-In-Duantes-Den (GIDD)

**GIDD: A Dual-Layer Malbolge '98 Video Codec & 8x8 Bayer Halftone Cinema Engine** by Gaston Dana (**GasMan** / `@gaston_pay_up`)

## Overview

GIDD scales Ben Olmstead's strict 1998 Malbolge virtual machine across a 240-frame, 24 FPS video clip. Malbolge uses a base-3 trinary architecture, a 59,049-word memory ceiling, the `crz` trinary operator, `rotr` (right rotation), and post-execution `xlat2` self-encryption. The checked-in 240-program archive contains 11,690,759 non-whitespace source characters, or about 11.7 million encoded Malbolge words. This is the archived source-word count; the exact number of executed instructions depends on each program's control flow.

The project has two related outputs: a visual halftone encoded in the spatial layout of each `.mal` source file, and a low-resolution RGB image emitted by executing that file in the Malbolge virtual machine. The Python builders compose these into 1080p, 24 FPS exhibition videos.

## The GIDD Dual-Layer Architecture

1. *98-Word C/D Causal Lookahead Window (Right Panel - 100% Executed `malbolge.c` Binary Stdout):* The generated program starts with ASCII 98 (`b`, opcode 4) at address 0. In the runtime, this decodes to the instruction that sets code pointer `C` to address 98; after the normal pointer advance, `C` is 99 and data pointer `D` is 1, a 98-address separation. The native C BFS compiler (`_mal_ppm_compiler.c`) models this as `C = 99`, `D = 1`, and examines post-`xlat2` encrypted data memory at `rt_mem[d + k]`. Its search depth is bounded to 16 words for image payload bytes and 60 for P6 header bytes; the 98 figure describes the pointer separation, not the BFS search depth. The compiler synthesizes a 5,389-byte binary 24-bit RGB Netpbm (`P6`, 56x32) stream per frame, including its 13-byte PPM header, inside the strict 59,049-word memory limit. The right panel captures the stream from the `<` output instruction in the native interpreter.

2. *8x8 Bayer Ordered Whitespace Halftoning (Left Panel - 100% Pure `.mal` Source Layout):* `build_pure_dithered.py` distributes each frame's executable opcodes across a 384x240 text grid using an 8x8 Bayer ordered dither matrix. Whitespace is ignored when the Malbolge program is loaded, so whitespace placement can shape the visible source without changing the instruction stream. Each saved `.mal` file is a standalone halftone print. In zero-video rendering mode, its midtone shading is reconstructed from that file's spatial character density, with no external video luminance read by the renderer.

3. *Zero-Video Proof Mode (`--from-mal-only`):* Reconstructs the 1080p, 24 FPS side-by-side exhibition video using the 240 `.mal` programs on disk and the output of the native Malbolge interpreter. The source MP4 is not needed for this mode.

## Quickstart & Reproduction Commands

Run all commands from the repository root. The builders require Python 3, OpenCV (`cv2`), NumPy, and a C compiler available as `cc`. The native terminal interpreter uses POSIX `usleep`.

### Mode 1: Zero-Video Proof Mode

Uses the checked-in frame archive without a source video:

```sh
python3 build_pure_dithered.py --from-mal-only
```

### Mode 2: Full 100% Pure Dithered Build from MP4

Builds the 240 standalone `.mal` files and the side-by-side exhibition video from a source clip:

```sh
python3 build_pure_dithered.py <video.mp4>
```

### Mode 3: Luminance-Assisted Side-by-Side Build

Builds the alternate side-by-side exhibition using the source clip's luminance for the code panel:

```sh
python3 build_side_by_side.py <video.mp4>
```

### Mode 4: 10-Frame ANSI Terminal Runner

Compile the native interpreter, then run either the combined animation or the individual frames in a POSIX-compatible ANSI terminal. The interpreter pauses 200 ms after each cursor-home sequence.

```sh
cc -O2 malbolge.c -o malbolge
./malbolge examples/terminal_10_frames/avalanche_all_10_frames.mal
```

To play the ten separate frames:

```sh
for f in examples/terminal_10_frames/frame_*.mal; do
  ./malbolge "$f"
done
```

`malbolge_240_pure_dithered_frames/` is the canonical, tracked 240-frame source archive. `malbolge_240_ppm_frames/` is an intermediate directory generated by `build_side_by_side.py` and is ignored by Git. Compiler binaries and temporary C sources are also generated on demand and ignored.
